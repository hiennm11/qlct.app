Contract: Month Close Flow

ADR-0056 (pending) · Epic 5 · 2026-06-15

§1 Context

App đã đầu tư rất sâu ở domain budget: live Budget, persisted BudgetSnapshot (history), draft BudgetPlan cho tháng tới, carry-over từ BudgetSnapshot.carryAmount, MonthlyReview read-only analytics.

Vấn đề: 4 capability riêng lẻ, user phải tự nối chúng vào 1 workflow. Cuối tháng user không có 1 hành trình rõ — từ "xem tháng vừa qua" → "hiểu carry-over" → "tạo/chỉnh kế hoạch tháng tới".

Mục tiêu Epic 5: orchestrate existing capability thành 1 luồng có chủ đích, không tạo khái niệm domain mới.

§2 Decision (overall)

5 thành phần (5 task), tất cả re-use domain primitives có sẵn:

  1. Entry rule — runtime heuristic (dayOfMonth >= 25), không persist lúc đầu.
  2. MonthCloseBanner — Card trên HomeScreen, dynamic copy theo plan state.
  3. Review-to-plan handoff — CTA cuối MonthlyReviewScreen deep-link sang MonthlyPlanScreen với source suggestion phù hợp.
  4. Carry-over explanation — copy ngắn giải thích +X ₫ chuyển từ tháng trước đang ảnh hưởng category nào (review + plan).
  5. Dismiss logic — key month_close_dismissed_{previousMonthYYYYMM} trong AppSettingsViewModel (reactive, mirror ADR-0050 pattern).

§3 Entry rule (§Task 5.1)

Quyết địnhSpec
CTA hiện khi dayOfMonth >= 25 (today là ngày 25 → hết tháng)
CTA ẩn khi User dismiss cho tháng đó (key month_close_dismissed_YYYYMM với YYYYMM = previous month) HOẶC dayOfMonth < 25
Target month semantics CTA "Xem tổng kết tháng này" → mở MonthlyReviewScreen với selectedMonth = previousMonth (tháng trước, đã kết thúc) — không phải tháng hiện tại đang chạy.
Runtime-only Tính mỗi build từ DateTime.now(). Không persist rule lúc đầu. Có thể add "always show" toggle ở Settings sau nếu user yêu cầu.
Edge case: tháng mới bắt đầu Ngày 1-24 tháng mới: CTA ẩn. Ngày 25+ mới hiện lại (với target = tháng vừa qua — month rollover case tự nhiên).

§4 MonthCloseBanner widget (§Task 5.2)

Card đặt giữa BudgetOverviewWidget và WeeklyReviewCard trên HomeScreen.

§4.1 Dynamic copy theo plan state

Query MonthlyPlanViewModel để check data.plan cho previousMonth + 1 tháng (= current month +1 = tháng tới target):

Plan stateCopy + CTA priority

Primary CTA: "Lên kế hoạch tháng tới" (icon Icons.event_note)
Secondary CTA: "Xem tổng kết" (icon Icons.bar_chart)

§4.2 Dismiss button

IconButton Icons.close ở top-right của Card. Tap → set dismiss key cho previousMonthYYYYMM (không phải current month). Snackbar 5s: "Đã ẩn gợi ý chốt tháng" + action "Hoàn tác" (mirror existing Undo pattern — clear key).

§4.3 Visual

Card với background nhẹ (colorScheme.primaryContainer hoặc surfaceContainerHigh), icon đầu heading, 2 button Row cuối. Mirror style WeeklyReviewCard (rounded 12px, padding 16).

§5 Review-to-plan handoff (§Task 5.3)

Cuối MonthlyReviewScreen (sau compare section, trước fixed expense hoặc cuối scroll), thêm 1 Card mới:

  • Heading: "Bước tiếp theo"
  • Body: "Dùng số liệu tháng này làm cơ sở cho kế hoạch tháng {nextMonthLabel}"
  • Primary CTA: "Lên kế hoạch tháng tới" → Navigator.push(MonthlyPlanScreen). Nếu đã có plan draft, copy = "Mở kế hoạch hiện tại".
  • Secondary CTA: "Chỉ xem" (đóng card, không navigate).

Source suggestion (xem §4.1) đã được MonthlyPlanScreen tự detect khi mở (xem MonthlyPlanViewModel._loadPlan ADR-0026 §Source resolution) — copy từ review/previous month snapshot sẽ tự fallback từ copy_previous_snapshot nếu chưa có plan. Không cần truyền source qua Navigator — VM đã handle.

§6 Carry-over explanation polish (§Task 5.4)

Hiện tại code đã có (ADR-0025 + ADR-0035):

  • BudgetSnapshot.carryAmount persist ở v14.
  • Monthly Review (past month) hiển thị "Còn dư chuyển tháng sau: +X ₫" per category (ADR-0035).
  • Budget overview current month hiển thị "Chuyển từ tháng trước: +..." (ADR-0032).

Polished copy ngắn (≤80 ký tự) inline ở 2 chỗ:

  1. Monthly Review (current month, applied plan path): dưới budget highlight, dim text 12px: "Carry-over từ {previousMonthLabel} sẽ áp dụng tự động khi tháng kết thúc" — chỉ khi user chưa có carry_amount set cho tháng hiện tại.
  2. Monthly Plan screen (draft state): trong total budget input, dim hint: "Số liệu carry-over từ {previousMonthLabel} sẽ được cộng vào khi áp dụng plan" — chỉ khi user chưa manually adjust total budget.

Không thêm field mới vào model — chỉ read BudgetSnapshot.carryAmount existing + check 1 boolean flag qua AppSettings key budget_carry_explained_YYYYMM (tương tự dismiss key, không annoy user).

§7 Dismiss logic (§Task 5.5)

Quyết địnhSpec
Key format month_close_dismissed_{YYYYMM} với YYYYMM = previous month (tháng cần chốt), không phải current month.
Storage SharedPreferences qua AppSettingsViewModel (ADR-0050 pattern). Reactive — Selector<AppSettingsViewModel, String?> watching dismissed key.
AppSettingsViewModel API String? getDismissedMonthClose(String yearMonth)
Future<void> setDismissedMonthClose(String yearMonth)
Future<void> clearDismissedMonthClose(String yearMonth) (cho Undo)
Auto-cleanup Không cần (key tự nhiên không relevant sau khi sang tháng mới vì check dayOfMonth >= 25 + previous-month mới). Nếu user tích luỹ 5+ key thì SharedPreferences rất nhỏ (<1KB).
Backup/restore Out of scope. month_close_dismissed_* là user-specific UI preference, không thuộc financial data. Mirror auto_purge_enabled precedent (ADR-0047).
