P1 — Reactive settings

Contract artifact for ADR-0050. Close known limitation from ADR-0047 §Consequences: "CategoryManagementScreen chỉ load autoPurgeEnabled một lần trong initState, nên nếu user đổi setting rồi quay lại khi screen vẫn còn mounted thì warning banner chưa cập nhật ngay." Refactor setting source từ AutoPurgePrefs static + load-once → AppSettingsViewModel (ChangeNotifier) + Provider. Settings screen + CategoryManagement cùng Consumer<AppSettingsViewModel>; toggle rebuild cả 2 reactive. Drop Task 1.2 (RouteAware) vì 1.1 (Provider VM) là standard pattern (8 ChangeNotifier sẵn trong main.dart).

§1 — Architecture: AppSettingsViewModel

New ViewModel ở lib/viewmodels/app_settings_viewmodel.dart, extends ChangeNotifier. Inject StorageService (the existing SharedPreferences facade) qua constructor. First field là autoPurgeEnabled (migrate từ AutoPurgePrefs). Thiết kế cho 6 P+ candidates (theme, currency, purge interval, voice lang, budget carry, clear all) — không phải 1-off. 

class AppSettingsViewModel extends ChangeNotifier {
  AppSettingsViewModel(this._storage);

  final StorageService _storage;
  bool _autoPurgeEnabled = true;
  String? _lastPurgeDate; // yyyy-MM-dd, null = chưa purge lần nào

  bool get autoPurgeEnabled => _autoPurgeEnabled;
  String? get lastPurgeDate => _lastPurgeDate;

  Future<void> load() async {
    _autoPurgeEnabled = _storage.loadValue<bool>('auto_purge_enabled') ?? true;
    _lastPurgeDate = _storage.loadValue<String>('last_purge_date');
    notifyListeners();
  }

  Future<void> setAutoPurgeEnabled(bool value) async {
    if (_autoPurgeEnabled == value) return;
    _autoPurgeEnabled = value;
    await _storage.saveValue('auto_purge_enabled', value);
    notifyListeners();
  }

  Future<void> setLastPurgeDate(String dateStr) async {
    _lastPurgeDate = dateStr;
    await _storage.saveValue('last_purge_date', dateStr);
    notifyListeners();
  }
}

Why AppSettingsViewModel, không phải SettingsViewModel: App* prefix tránh name shadow với SettingsScreen, signals "app-config layer" (distinct from domain VMs: Expense/Budget/Category/Recurring/QuickTemplate/Backup/MonthlyReview/MonthlyPlan).

Provider wiring (lib/main.dart:226-290): add 1 ChangeNotifierProvider<AppSettingsViewModel> ở top of providers list. Order matters vì sau này có thể có VM khác depend on AppSettings (ví dụ CategoryViewModel nếu purgeOldTrash ships). Place first → downstream VMs có thể inject qua ChangeNotifierProxyProvider tương tự pattern Expense→Budget.

§2 — SettingsScreen binding

SettingsScreen drop _loadAutoPurgePref + _setAutoPurgePref local state. Wrap auto-purge row trong Selector<AppSettingsViewModel, bool> (hoặc Consumer). On change: context.read<AppSettingsViewModel>().setAutoPurgeEnabled(value). Lifecycle: initState gọi context.read<AppSettingsViewModel>().load() một lần (idempotent — VM cache lần đầu read).

§3 — CategoryManagementScreen trash banner binding

Drop _autoPurgeEnabled local state + _loadAutoPurgePref method + AutoPurgePrefs import. Wrap _buildTrashWarningBanner call trong Selector<AppSettingsViewModel, bool> — banner gate chuyển từ if (!_autoPurgeEnabled) (stale, load-once) → if (!appSettings.autoPurgeEnabled) (reactive, Consumer rebuild on VM notify). 

// Before (ADR-0047 — load-once, stale after toggle):
if (!_autoPurgeEnabled) return const [];
final approaching = vm.itemsApproachingPurge();
...

// After (ADR-0050 — reactive):
Selector<AppSettingsViewModel, bool>(
  selector: (_, s) => s.autoPurgeEnabled,
  builder: (context, autoPurgeEnabled, _) {
    if (!autoPurgeEnabled) return const SizedBox.shrink();
    final approaching = vm.itemsApproachingPurge();
    if (approaching.isEmpty) return const SizedBox.shrink();
    // ... existing banner widget ...
  },

Key binding (giữ nguyên): state-trash-purge-warning ở line 715 category_management_screen.dart. Banner visible ⇔ autoPurgeEnabled == true AND itemsApproachingPurge.isNotEmpty.

§4 — Reactive assertion (the core fix)

Known limitation ADR-0047: "nếu user đổi setting rồi quay lại khi screen vẫn còn mounted thì warning banner chưa cập nhật ngay." Reactive shape close gap: notifyListeners trong setAutoPurgeEnabled rebuild tất cả Selector<AppSettingsViewModel, bool> instances trong tree — KHÔNG cần pop Settings và KHÔNG cần RouteAware.

  1. State A — initial: CategoryManagement mounted, banner hiển thị vì autoPurgeEnabled=true + 1 item approaching purge. Settings chưa mở.
    Key visible: state-trash-purge-warning.
  2. State B — push Settings, toggle OFF: User tap gear menu → push SettingsScreen. Toggle auto-purge OFF → setAutoPurgeEnabled(false) → VM notifyListeners. CategoryManagement vẫn mounted (route dưới stack).
    Nếu dùng Task 1.2 (RouteAware): banner vẫn hiển thị cho đến pop.
    Nếu dùng Task 1.1 (Provider VM): banner biến mất NGAY, trước cả pop.
  3. State C — pop Settings: User pop về CategoryManagement. Banner đã ở đúng state (State B result). Pop là no-op cho state, chỉ unmount Settings route.
  4. State D — re-toggle ON (từ CategoryManagement hoặc Settings lại): Banner xuất hiện lại. Pop không cần thiết.

User-visible value: reactive — feedback loop close trong ~16ms (1 frame rebuild), không cần round-trip qua navigation. Bài học từ ADR-0017 §Slice 5 (revert "drop ProxyProvider → manual listener"): cross-VM reactivity qua Provider là path of least resistance trong codebase này.

§6 — Out of scope (explicit defer)

  1. Task 1.2 (RouteAware fallback) — dropped. YAGNI vs 8 ChangeNotifier precedent (main.dart:226-289). RouteAware doesn't scale to 6 P+ candidates (ADR-0047 §5). Revisit chỉ khi user explicitly opt out của Provider pattern.
  2. Restore-from-backup interaction với auto_purge_enabled + last_purge_date. Backup schema v9 (CONTEXT.md line 18) KHÔNG backup settings. Edge case: restore từ 60-day-old backup với trash items >30 days old — current last_purge_date flag block re-purge (giữ value "today"). Real bug, nhưng orthogonal to this epic. Flag ADR-0050 §Future work.
  3. CategoryViewModel.purgeOldTrash call site migration. Unshipped in current branch (ADR-0045 §implement pending). Khi ship, prefer context.read<AppSettingsViewModel>().autoPurgeEnabled over static AutoPurgePrefs.isEnabled(). Out of scope here.
  4. 6 P+ Settings candidates (theme, currency, purge interval, voice lang, budget carry, clear all) — mỗi cái cần grill + contract + ADR riêng per ADR-0047 §5.
