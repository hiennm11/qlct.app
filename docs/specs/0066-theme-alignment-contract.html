§2 — Decision: bundle Inter qua assets/fonts

Pin Inter làm default font. Lý do bundle .ttf thay vì google_fonts:

  1. ADR-0055 ceiling 1.8s cold start — đã chứng minh native ceiling không thể optimize thêm từ Dart. Online font fetch + cache miss thêm 200-500ms flicker là budget không afford được.
  2. Offline-first constraint — personal finance app, user dùng offline thường xuyên (xe ôm, metro). Inter phải render 100% kể cả khi mất mạng.
  3. APK size negligible — qLCT.app 58.4MB release, thêm 4 file .ttf (~250KB) = 0.4% growth.
  4. Predictable release gate — ADR-0024 §3 không yêu cầu test offline, nhưng thêm external dep = thêm 1 failure mode chưa có mitigation. Bundle 1 lần, 0 network, 0 surprise. 
# pubspec.yaml — flutter.fonts section
flutter:
  uses-material-design: true
  fonts:

File nguồn: download Inter v4.0 từ github.com/rsms/inter (SIL Open Font License 1.1 — free cho commercial). Chỉ lấy 4 weight (400/500/600/700) khớp Stitch design system typography scale. Không include Inter Italic (codebase không dùng italic body).

§3 — AppColors: pin error = #BA1A1A

Codebase hiện AppColors.error = Color(0xFFFF5459) (lighter red, ~"salmon"). Stitch design system dùng #BA1A1A (Material 3 standard error). Drift này đã ship 1.7.0 nhưng chưa có user-visible complaint (chỉ dùng cho error SnackBar background + error icon tint, ít visible).

Không bump schema, không backup impact. error chỉ dùng cho UI tint — không persist giá trị hex nào trong SQLite hay backup JSON. Đổi hex chỉ thay đổi visual, không data integrity risk.

Regression check: grep AppColors.error across lib/ → chỉ dùng trong theme.dart ColorScheme + 4-5 sites (SnackBar background, Icon tint). Visual diff chấp nhận được (đậm hơn 1 tone, semantic "error" rõ hơn).

§4 — ElevatedButton shape: pill

Stitch design system định nghĩa button = "fully rounded (pill) shape for primary actions to make them highly tappable". Codebase hiện dùng BorderRadius.circular(8) (8px rounded, không pill). 

// lib/core/theme.dart — diff (elevatedButtonTheme)
elevatedButtonTheme: ElevatedButtonThemeData(
  style: ElevatedButton.styleFrom(
    backgroundColor: AppColors.primary,
    foregroundColor: Colors.white,
    elevation: 0,
    padding: const EdgeInsets.symmetric(horizontal: 24, vertical: 12),
-   shape: RoundedRectangleBorder(
-     borderRadius: BorderRadius.circular(8),
-   ),
+   shape: const StadiumBorder(),
  ),
),

Trade-off: 1 site sẽ visually lệch — RecurringEditDialog / BudgetBulkEditDialog / TransactionEditDialog primary button từ 8px rounded → full pill. Padding ngang có thể tăng 4-8px (pill tự nới rộng theo content + padding). Test visual sau khi land: install trên test device, mở 3 dialogs verify không overflow button text.

Key binding: không cần Key mới (button không có state phụ thuộc). Test qua find.byType(ElevatedButton) + visual regression checklist trong release smoke test.

§5 — ActionChip shape: soft 4px

Stitch design system định nghĩa chip = "4px (Soft) radius to differentiate from larger interactive components". Codebase dùng ActionChip default = StadiumBorder (~20px = pill). Drift đáng kể — chip hiện tại trông "bo tròn hoàn toàn" trong khi Stitch design muốn "vuông nhẹ".

Caveat: ActionChip không có global theme override như button. Phải sửa trực tiếp trong ChipThemeData của ThemeData:

  colorScheme: ...,
  // ... existing
+ chipTheme: ChipThemeData(
+   shape: RoundedRectangleBorder(
+     borderRadius: BorderRadius.circular(4),
+   ),
+   side: const BorderSide(color: AppColors.border),
+   backgroundColor: AppColors.surface,
+ ),
  elevatedButtonTheme: ...,
  // ... rest
);

Scope check: grep ActionChip( + Chip( across lib/ → tất cả sites dùng chip (QuickAddBar category chip, QuickTemplatesStrip template chip, transaction filter chip, voice result chip) đều pick up ChipThemeData override. 0 site hardcode shape: trực tiếp.

Visual diff: chip từ "pill hoàn toàn" → "vuông 4px nhẹ". Side border 1px #E0E0E0. Backdrop surface white. Kết hợp với button pill (§4) tạo visual hierarchy rõ: button = pill (primary action), chip = soft 4px (secondary/filter).

§6 — primaryContainer: Material 3 auto-derive

Stitch design system dùng primaryContainer: #208091 (= primary solid, container tone same as primary). Codebase hiện KHÔNG pin primaryContainer — ColorScheme.light() tự derive lighter tone từ primary seed.

Decision: giữ M3 auto-derive. Lý do:

  1. 1 site coupled hiện tại: MonthCloseBanner (ADR-0056) dùng colorScheme.primaryContainer cho banner background. Đã ship 1.7.0, chưa có bug report. Pin cứng = lock banner vào 1 tone.
  2. Dark mode future-proof: nếu ship dark mode sau (P+ candidate ADR-0047 §3), M3 derive tự adapt — pin cứng phải duplicate cho dark scheme.
  3. Trade-off aware: derive có thể produce tone hơi khác Stitch design system. Acceptable — banner vẫn teal family, contrast OK cho onPrimaryContainer text.

Code change: 0 dòng. Status quo. Document trong ADR để future contributor không over-pin.
