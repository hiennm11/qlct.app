§1 Context

Sau Epic 6 user báo chart trên Home "vỡ hình". Audit 2026-06-16 tìm ra 2 bug ở lib/widgets/chart_widget.dart:

  • Bug A: Legend bên phải (Row flex 1) có height bị constraint = 250-24=226px (từ SizedBox(height: 250) + SizedBox(height: 24) trên header). User có 8-12 danh mục thật → legend content > 226px → RenderFlex overflow dọc.
  • Bug D: PieChartSectionData.title = "12.5%" inline trong slice. Slice nhỏ (vd 1-3% = góc 3.6-10.8°) thì text fontSize 12 bold rộng hơn slice góc → bị cắt/chồng lên slice khác.

§2 Bug #1 — RenderFlex overflow dọc

❌ Before

SizedBox(height: 250)
  → Row
      → Expanded flex 2 (PieChart)
      → SizedBox(width: 16)
      → Expanded flex 1 (_Legend ListView shrinkWrap)
                       ↑ height = 250 - 24 (header) = 226px
                       ↑ legend content > 226px → OVERFLOW

✅ After

SizedBox(height: 280)
  → Row
      → Expanded flex 2 (PieChart)
      → SizedBox(width: 16)
      → Expanded flex 1
          → SingleChildScrollView
              → _Legend content (Column)
                               ↑ scroll khi > 256px

Fix: (a) bump SizedBox 250→280px (thêm 30px headroom cho 1-2 danh mục extra). (b) Wrap legend content trong SingleChildScrollView để scroll dọc khi content > available height. Pattern mirror ADR-0052 §3.2 (small-height viewport audit).

§3 Bug #2 — Inline % label bị cắt/chồng

❌ Before — 8 danh mục, 1.5% slice

1.5% 12.5% 8.0%

Slice 1.5% góc 5.4° → text "1.5%" rộng ~25px tràn ra ngoài

✅ After — clean slice, % chỉ trong legend

Slice chỉ có color, legend hiện "🍔 Ăn ngoài — 1.5% — 50.000 ₫"

Fix: Drop PieChartSectionData.title inline. Slices chỉ có color (visual cue). Percentage hiển thị trong _Legend row bên cạnh amount (vd "1.5% · 50.000 ₫"). Logic tính % giữ nguyên ((value / total * 100).toStringAsFixed(1)).

§5 Legend scroll policy

  • Scroll direction: vertical (default SingleChildScrollView).
  • Physics: ClampingScrollPhysics() cho nested scroll trong CustomScrollView của HomeScreen.
  • Không có "Xem thêm" button — toàn bộ danh mục scroll được, không cap.
  • Empty state khi categoryTotals.isEmpty: render centered "Chưa có dữ liệu" card, không có chart (giữ nguyên ADR-0016 D5).

§6 _createSections rule (drop inline title)

List<PieChartSectionData> _createSections(
  Map<String, int> categoryTotals,
  List<Category> activeCategories,
) {
  final total = categoryTotals.values.fold(0, (sum, val) => sum + val);
  final colors = AppColors.categoryColors;

  return categoryTotals.entries.map((entry) {
    // ADR-0036: deterministic color by categoryId hash.
    final color = colors[entry.key.hashCode.abs() % colors.length];

    return PieChartSectionData(
      value: entry.value.toDouble(),
      // No `title` field — slice clean, only color. % moved to legend.
      color: color,
      radius: 80,
    );
  }).toList();
}

Lưu ý: Giữ nguyên memoization logic (ADR-0017 D5.2). _cachedSections chỉ recompute khi stats hoặc active categories đổi.

§7 Removed components

  • title: '$percentage%' trên PieChartSectionData (gây cắt/chồng).
  • titleStyle: TextStyle(fontSize: 12, fontWeight: bold, color: white) (chỉ dùng kèm title).

§8 Kept components

  • SectionHeader (ADR-0011) — emoji + title, no action.
  • Empty state (ADR-0016 D5) — 48px emoji + message khi không có data.
  • Loading state (ADR-0016 D5) — CircularProgressIndicator khi isLoading.
  • Memoization cache (ADR-0017 D5.2) — _cachedSections skip recompute.
  • Color by id hash (ADR-0036) — stable color qua runs.
  • ADR-0066 theme — Card + Padding(16) + SectionHeader style.

§9 Trade-offs

Trade-off 1: Drop inline %

User mất glance % trên chart → phải map slice→legend để biết %. Trade-off chấp nhận được vì (a) chart giờ clean hơn, (b) legend có % inline cạnh amount nên tra cứu 1-tap.

Trade-off 2: SizedBox 250→280

Chart block trên Home cao hơn 30px → scroll xuống phải nhiều hơn. Trade-off chấp nhận được vì giải quyết overflow dứt điểm, không cần giải pháp phức tạp hơn (aspect ratio, dynamic height).

§10 Edge cases
