# 0068 — Flutter 3.38.5 → 3.44.2 SDK upgrade

Date: 2026-06-16
Status: accepted
Build: `1.8.0+2026061603` (RC bump on BUILD, no new tag — see ADR-0024 hotfix pattern)

## Context

Local Flutter SDK was on 3.38.5 (Dec 2025); stable channel now ships 3.44.2
(released 2026-06-10, 5 days before this change). Two minor versions behind,
~6 months of framework drift. Want to keep SDK reasonably current to avoid
bigger-jump pain later and to pick up Material 3 fixes.

Global SDK upgrade (machine-wide at `C:\Users\yoga\flutter`), not per-project.

## Decision

- `flutter upgrade` → 3.44.2 stable. `flutter --version` confirms.
- `pubspec.yaml`: `environment.sdk: ^3.10.4` → `^3.12.2` to match new Dart.
- `flutter pub get` → 5 transitive deps bumped (test_api 0.7.7→0.7.11 etc.,
  all patch-level). 61 packages have newer versions but stay on `^` constraints
  — not auto-bumping majors in this change.
- Auto-fix deprecations surfaced by new SDK:
  - `ReorderableListView.onReorder` → `onReorderItem` (1 hit,
    `lib/views/category_management_screen.dart:585`). **Important**:
    `onReorderItem` auto-adjusts `newIndex` for the removed item, so the
    manual `newIndex - 1` adjustment previously done in this code is now
    redundant and was removed. Comment updated to call this out.
  - `DropdownButtonFormField.value:` deprecation warning — already ignored
    via `// ignore: deprecated_member_use` but the comment was on the wrong
    line. Moved ignore comment to the `value:` line itself.

## Consequences

- `flutter analyze`: 76 → 93 info issues. All info-level (lints + remaining
  intentional deprecations from `DropdownButtonFormField` and Material 2
  patterns still in use). Zero errors, zero warnings. The 17 new info
  issues are from the new Dart/Flutter lints shipping with 3.44.
- `flutter test`: 1114 pass, 2 fail. The 2 failures
  (`monthly_review_screen_test.dart: overflow guard` × 2) are
  **pre-existing** — also failed on 3.38.5 baseline. Not regressions.
  Tracked separately as test drift.
- `lib/views/category_management_screen.dart` reorder behavior: now uses
  Flutter 3.44+ `onReorderItem` API. Existing test
  `CategoryManagementScreen smoke dragging a category row does not throw`
  (and 47 other category tests) pass — verifies the manual-`-1`-removal
  was correct.
- Branch state: changes are on `epic-6-theme-alignment-note-first-home`
  (per user direction — global upgrade, no separate branch). Build bumped
  `2026061602` → `2026061603` (no new git tag, hotfix pattern per
  `install-hotfix-procedure.md`).
- Backup test drift baseline: backup_* tests passed in isolation on 3.44.2
  (failed only in the full baseline run on 3.38.5 — likely cross-test
  FFI SQLite state leak, pre-existing). Not a 3.44 regression.

## Followup (not blocking this change)

- The 17 new info lints could be addressed in a follow-up housekeeping
  commit per `pre-existing-test-drift.md` pattern.
- `monthly_review_screen_test` overflow failures warrant investigation —
  possibly a `setSurfaceSize` regression on the new Material 3 widget
  metrics, but unrelated to this upgrade's scope.
- `flutter pub upgrade --major-versions` is a separate, larger decision
  (sqflite 2.4→3.x, sentry_flutter 8→9, etc.) — explicitly out of scope.
